== What this file is

This is the working memory for whoever picks the deck up next, human or agent. `CLAUDE.md` at the repository root tells an agent to read it before doing anything else. It holds what the repository and its history do not: how the author wants the work done, what was decided and why, what is still open, and where on the author's machines the source material lives.

It exists because agent sessions do not share memory across machines. A session's private memory stays on the host it ran on, so anything worth keeping is written here, where a clone carries it. `docs/notes.adoc` is the companion file: it records the thinking behind each concept in the talk. This file records the state of the work.

Keep it current. When a decision is made, an open point is closed, or a fact here turns out wrong, edit this file in the same change. Delete what has gone stale; do not append a correction beneath it.

== The repository is public

`rudolphpienaar/ChRIS-overview` is a public GitHub repository, and every push to `master` publishes the deck to GitHub Pages. The HARBOR Task Description Document is an internal deliverable still under negotiation. Nothing from it may be quoted here, in the notes, or on a slide beyond what the deck already states at the level of task names. No budget figures, no milestone text, no partner detail.

== How the author works

The author is Rudolph Pienaar, chief architect of ChRIS. The standing rules are in the author's global instructions and style guides; the ones that have mattered most here follow.

The work is additive. Existing slides stay unless the author says otherwise. The author dictates a concept, the agent gives its thoughts first, and slides are written on the author's word. Small, explicit corrections ("replace X with Y") are made directly.

Never commit unless asked, and never push without confirming. Branch before changing anything on `master`.

Every claim on a slide carries a source that has been checked, and the full reference goes in `docs/refs.bib` with a note saying how it was read. Where a line is the agent's own wording or an inference, `docs/notes.adoc` says so.

Prose in `docs/` is AsciiDoc, one paragraph per line, in plain technical register, with no em-dashes. Report what was verified and what was not. The author checks.

== Building and viewing

The deck is `talk.sd`, written for slidedown with the `command-line` theme. Build it from the repository root:

[source,bash]
----
uv run --project ~/src/slidedown slidedown . talk --inputFile talk.sd --theme command-line
cd talk && python3 -m http.server 8000
----

The build is the test: an unresolved menu target is a build error, and a successful build reports the slide count. As of 2026-11-12 that count is 52. slidedown `main` is at `3e22e35` and the Pages workflow pins that same commit. An older slidedown checkout either fails with an unknown theme or builds the deck without the behaviour below, so pull it first.

Code and API payloads on a slide are syntax coloured. The author set this rule on 2026-11-11. Use slidedown's own `.code{.syntax{language=...}}` block for it, not hand-marked HTML. It works inside a terminal window and inside a reveal. Fenced Markdown blocks are not processed there, and the `http` language mis-colours bare request lines, so a list of REST calls is better drawn as a figure with the verbs marked.

A menu entry must read exactly as the heading of the slide it lands on, character for character. The author set this rule on 2026-11-11 after a menu said "A machine, not an endpoint" and landed on a slide headed "ChRIS as a Computer". When a slide is retitled, change its menu entry in the same edit. All twenty menu entries were checked against their headings that day.

The deck relies on three slidedown behaviours that were added for it on 2026-11-11 and are in `main` from `4651934`. A typewriter in a terminal window shows its prompt at once, types only the command and prints the output beneath it in one step, with the cursor after the command; the `chell` session slides use this. Highlighted code sits on a terminal window's background with no box of its own; the code slides in the mise section use this. Up and Down pan a slide taller than the page and otherwise go to the first and last slide; "The Whole Stack" uses this. If one of these looks wrong, check the slidedown commit before changing the deck. A fourth dependency arrived the same day in two commits, `132c100` and `3e22e35`: the `command-line` theme ships Fira Code as one file and names it on `pre` blocks. Before that a figure took the browser's own monospace font. On Android that font has no box-drawing characters, they came from a fallback about 18% wider than the letters, and every figure broke; pannotia hid the fault because its system monospace carries those characters at the same width. Shipping the font alone did not fix it, since the figures were not using it. The author confirmed the fix on an Android tablet on 2026-11-11, on the local build. Don't move the pin behind `3e22e35`, and check any new figure on a device other than the one it was drawn on. With Fira Code the figures are about 2.5% wider than they were on pannotia; only the final Architecture step was rechecked for fit.

The mise section's last menu entry, "A Live chell" (`mise-live`), puts a working `chell` on a slide. `scripts/chell-live` starts `ttyd` on loopback port 7681, which serves xterm.js and runs the given `chell` command under a pseudo-terminal on the presenting machine; the slide loads that page in a frame when clicked. It works only when the deck is opened as `localhost` on the machine running the script. Anywhere else, the public site included, the click prints one line saying so. The reasoning is in `docs/notes.adoc` under "A live chell on a slide". As of 2026-11-11 the slide has been tested with `ttyd` 1.7.7 on pannotia running a harmless command: the terminal draws in the slide at a matching size and colour, and `ttyd` listens on loopback only. It has not been tested with `chell` against the remote session, and the keyboard handover (click in the terminal to type, click outside for the deck's arrow keys) has not been tried by hand. The author attaches to pangea with `chell --remote --attach <url> --token <token>`, both of which change with each daemon, so the command is passed to the script at run time and never written down here.

Slides are brief. The author set the rule on 2026-11-11: short fragments, at most four bullets where the content allows, about six words each, one highlighted word per bullet. Every slide follows it as of that day, at a mean of 23 words a slide where it had been 49. The full sentence a fragment stands for belongs in `docs/notes.adoc` under "Speaking lines", not on the slide. Two deliberate exceptions: "So What Is ChRIS?" keeps five quoted answers at full length because they are quotations, and "The Five Questions" has five bullets because it is a list of five.

Unknown keys inside `.meta{}` are ignored silently, so a typo there shows up only in the rendered page. Check new slides in a browser. Figures are `<pre class="fig">` blocks styled in `.meta{css:}`; that rule sets `overflow: visible` because the theme's default drew a scrollbar on every figure.

== Where the deck stands

The outline has eleven entries. The first, "The Unbearable Lightness of Defining", is new and is the only concept the author has dictated so far; `docs/notes.adoc` has its reasoning in full. It asks what an iPad is, shows that answers from experience fail when the UI changes, and carries the test over to ChRIS. Its "So What Is ChRIS?" slide lists five answers people give. A slide after it, "One Kernel, Two Surfaces", maps iPadOS and macOS over Darwin onto ChRIS_ui and `mise` over CUBE; the mapping is the author's, the slide wording is the agent's and unreviewed. Four are the author's wording and the fifth ("A workflow engine") is the agent's stand-in.

The architecture section was corrected on 2026-11-11. `pman` is gone from it, since `pfcon` absorbed it in 2025. `mise` has its own outline entry after "Architecture", a menu of seven entries, one of which ("One Intent, Four Ways") is a menu of its own, three levels down from the outline. `docs/notes.adoc` describes it. Its claims were checked by the `mise` session on 2026-11-11 and corrected; the notes list what changed. The `mise` repository now lives at `HARBOR-Medical-AI/mise`.

`chrs` is deprecated and must not appear. The current client stack is `mise`, with `chell` as its shell surface and ARGUS as its web surface. The HARBOR audience has already seen ARGUS.

== Open points

The HARBOR slides were first written from a LaTeX TDD that has since been retired. On 2026-11-11 the session that maintains the HARBOR milestones work checked twenty claims from those slides against the current authority, which is a spreadsheet the deck's agent cannot read. Seven held, eight had changed and five were no longer there. The five HARBOR slides ("Where ChRIS Sits in HARBOR", "The Boundary", "Ingestion as Apps", "What HARBOR Adds to ChRIS", "Governance and Standards") were rewritten to match, along with one line each on "Workflows and Provenance" and "What We Need to Agree" (a slide the author cut on 2026-11-12). `docs/notes.adoc` records what changed and why. The author has not yet reviewed the rewrite.

That session cleared nothing for public release; it said the decision is the author's. The rewrite therefore stays at the level of architecture, paraphrases throughout, cites sections of the document by name with no task numbers, and leaves out thresholds, dates, third parties and the performer structure. The author should confirm that this level is acceptable on a public page before the branch is pushed.

The current authority does not mention `mise`, `chell`, ARGUS or berths. They belong in the architecture section as ChRIS engineering and must not be presented as HARBOR commitments.

The word "plugin" appears across the deck. The current HARBOR authority says "app" or "ChRIS application" almost without exception. Only the HARBOR slides were changed to match.

Apache Airflow must not appear. It was on the "What HARBOR Adds to ChRIS" slide as the top layer of the figure and in one bullet, and the author objected. It came from the retired LaTeX, where the name survived in a subtask title and in labels after a pass to technology-neutral language. The same session confirmed that the current authority does not name Airflow at all and treats ChRIS itself as the orchestration layer. The slide's figure now shows the Hub dispatching to a Spoke, with no scheduler product named.

The author spoke of "berth triggers" as part of what replaces an external scheduler. The `mise` session found nothing by that name in code or docs. A schedule is `chell -c` under cron and nothing more. Do not put triggers on a slide unless the author says where they are.

The pfcon bullet lists OpenShift among its compute environments. The `pfcon` README names Docker, Podman, Swarm, Kubernetes and SLURM.

With eleven outline entries, the last two are out of reach of the number keys, which stop at nine.

The new "So What Is ChRIS?" slide and the older "What Is ChRIS?" section overlap. Both are kept for now.

The figures were redrawn on 2026-11-11 in the manner of the `mise` README's architecture figure: every component a box, layers stacked, a trust boundary in double lines, notes dimmed in the margin. `docs/notes.adoc` has the reasoning. The author asked for the redraw but has not reviewed the result. Some slides are now taller than the page and rely on Up and Down panning. "Architecture" is not one of them any more: it builds its figure in seven steps inside one slide, with the newest part in yellow and CUBE drawn as a cube whose top face is the API, each step a revealed line whose figure replaces the last, and a new slide, "One DAG, Many Substrates", follows it, showing one DAG in CUBE spread over three `pfcon` instances on OpenShift, Slurm and k8s. On that slide the DAG sits in CUBE, `pfcon` holds one job per node and OpenShift one pod per job; the author had the DAG moved out of `pfcon`. The author dictated the steps of both slides but has not reviewed the rendered result. New figures should follow the same conventions; a bare word with an arrow is no longer acceptable as a component.

Three slides in the HARBOR roadmap section, on how one ChRIS talks to another, carry a recommendation that is the agent's and not yet the author's decision: a stateless HTTP intent API for Hub-to-Spoke dispatch, the session WebSocket for telemetry, and MCP for agent clients. The last slide labels each as funded, planned or proposed. The author asked for the slides but has not reviewed the wording.

The laptop line on the "Mobile OS" slide and the "workflow engine" answer are the agent's. The author may want to replace them.
